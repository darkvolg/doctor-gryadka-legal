2. Какие данные мы собираем

2.1. На этапе бесплатного использования (текущий режим)

Приложение работает в анонимном режиме. Мы НЕ запрашиваем и НЕ собираем:

  • Имя, фамилию, отчество
  • Email, номер телефона
  • Адрес проживания
  • Точные координаты GPS

Автоматически создаваемые данные:

  • Анонимный идентификатор сессии (UUID, не привязан к личности пользователя) — необходим для технической работы приложения и сохранения истории диагнозов между запусками.
  • Фотографии растений, загруженные пользователем для диагностики.
  • Метаданные диагноза: дата создания, определённое заболевание, рекомендация по уходу.

2.2. На этапе платной подписки (будущая версия)

При оформлении подписки RuStore/Google Play обработка платежа происходит на стороне магазина приложений. Мы получаем от магазина только:

  • Токен подписки (для проверки активного статуса)
  • Срок действия подписки

Email, ФИО, реквизиты оплаты к нам не поступают.

4. Передача данных третьим лицам

4.1. Передача фотографий для AI-обработки

В момент диагностики фотография растения передаётся в AI-сервис OpenRouter (openrouter.ai), который маршрутизирует запрос в модель Google Gemini Vision.

  • Фотография передаётся по защищённому соединению (TLS).
  • Фотография обрабатывается в реальном времени для генерации диагноза, не сохраняется ни в OpenRouter, ни в Google.
  • Согласие на такую передачу даётся пользователем при использовании функции диагностики.

4.2. Хранение данных

Данные хранятся на серверах Supabase Cloud (платформа Backend-as-a-Service). Регион хранения: Франкфурт (Германия), eu-central-1.

⚠️ Важно: на этапе free-launch (запуск без сбора персональных данных) хранение анонимных данных в зарубежной инфраструктуре допустимо. При переходе на платную подписку и сбор персональных данных (email и пр.) данные будут перенесены на территорию РФ (Yandex Cloud / Selectel) согласно ч. 5 ст. 18 152-ФЗ.

4.3. Передача в иные сервисы

Мы не продаём, не передаём в маркетинговые цели и не делимся вашими данными с третьими лицами, кроме случаев, прямо описанных в пунктах 4.1 и 4.2.

7. Меры безопасности

Для защиты данных применяются:

  • TLS-шифрование при передаче данных
  • Изоляция данных пользователей через Row-Level Security (RLS) в базе данных
  • Регулярные обновления серверной инфраструктуры
  • Минимизация собираемых данных (принцип «собирать только необходимое»)
